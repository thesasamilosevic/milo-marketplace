# Formatting Rules

## Heading Architecture

### Hierarchy Overview

- H1 (#)
- H2 (##)
- H3 (###)
- Bold coloured span, spaced all-caps, used as a section label inside callouts
- Plain coloured span, spaced all-caps, no bold, used as a sub-label inside callouts
- H4 (####) is never used

### How ABBI Chooses Heading Level

Evaluate three factors when selecting heading levels:

- Volume: amount of text following the header
- Structure: whether content requires parts, sections, or steps
- Purpose: type of page such as note, framework, template, or document

### Scenario A, Small Content Block

- Use H3 as the main header
- Use a bold coloured span for any label beneath it
- Do not use H1, H2, or H4

### Scenario B, Medium Content Block

- Use H3 as the primary header
- Use a bold coloured span for any sub-label below H3
- Place bullets underneath the headers

### Scenario C, Large Content Block

- Use H2 for main sections
- Use H3 for subsections
- Use a bold coloured span for any deeper label below H3

### Scenario D, Full Document

- Use H1 for parts
- Use H2 for sections
- Use H3 for steps
- Use a bold coloured span for detail labels below H3
- Allow multiple H1 headings for documents with multiple parts

### Toggle Behaviour

- When there are multiple H2 headings convert all H2s to toggles
- Use H3 toggles for long subsection lists
- Use H1 toggles for collapsing entire parts

### No H4 Rule

- H4 (####) is never used in MILO.LIFE.OS
- What was previously called 'H4' was always a plain bold all-caps text block, not an actual Notion heading
- Now that Notion renders #### as a real heading element, it must not be used
- When a lightweight label is needed below H3, use a bold coloured span: L A B E L in the appropriate pillar colour

### Formatting Principles

- Do not use decorative headings
- Avoid skipping heading levels
- Reset the heading scale for each major section
- All page content sits inside one outer callout. Never place headings, labels, or content directly on the page canvas
- Never place a divider (---) between sections inside a callout. Dividers are used only immediately after a callout header label

## Callout Formatting Rules

### Text Rules

- Full sentences end with periods
- Add a single space after end punctuation inside callouts
- Insert two line breaks after each complete thought
- Do not use punctuation at the end of bullet items
- Do not use em dashes
- Use parentheses only for brief clarifications
- Use single quotation marks for system terms

### Section Callout Pattern

- When formatting coaching prompts, each category must be one callout
- Do not split a category into separate callouts for reference, prompts, or secondary questions
- Use default callouts only. Do not apply callout background colours unless explicitly requested
- Do not colour or highlight callout headers
- Callout header spacing standard: one space between every letter, two spaces between every word
- Inside the callout, use this order:
  1. Category title (header spacing standard)
  2. P R I M A R Y  Q U E S T I O N
  3. Primary question as a bullet
  4. P R O M P T S
  5. Numbered prompts
- References and secondary questions become prompt lines inside the same callout, with nested bullets only when needed

### Emphasis Rules

- Use bold for key concepts
- Use bold and underline together only for rare emphasis
- Use italics only inside direct quotes
- Never mix bold and italics

### Date and Number Rules

- Use natural dates like December 4, 2025
- Use system timestamps in the format YYYY.MM.DD
- Do not use Roman numerals in callouts

### Spacing Rules

- Add space only when it improves clarity
- Do not apply rigid before or after spacing rules
- Avoid visual crowding

### Callout Structure

- Opening Line: keep it short, steady, and direct
- Body: use short paragraphs or lists
- Closing Line: treat as optional

### Toggle Callouts

- Inside toggle callouts use regular text only
- Use bold miniature section labels
- Use bullets or numbers for structure

### When Not To Use Callouts

- When content is obvious
- When reflection is needed
- When a callout interrupts flow

## List and Bullet Rules

- Primary bullet: use a solid bullet as the default list style
- Secondary bullet: use a hollow bullet for secondary list levels
- Tertiary bullet (rare): use a square bullet only when a third layer of hierarchy is required
- Action lists: use Notion checkboxes [ ] for tasks only
- Numbered lists: use when order or sequence matters. Use 1, 2, 3 for main steps, 1.1, 1.2 for sub-steps under a main step
- Roman numerals: reserve for large structural divisions in long documents
- Keep one idea per bullet, no punctuation at the end of bullets, mix bullet types only when hierarchy requires it, no emoji as bullets, treat spacing as contextual, allow nested lists to follow Notion's default indentation

## Colour Rules

- Pillar colours: Design uses green, Energy uses blue, Purpose uses red, Lifestyle uses purple
- Universal colour: use yellow for universal databases and cross-pillar content. MILO.LIFE.OS™ will be yellow regardless of pillar location
- Maintenance colour: use grey for maintenance tasks, upkeep, and OS infrastructure
- Highlighting tiers: Tier 1 uses the relevant pillar colour, Tier 2 uses orange, Tier 3 uses pink

### Cross-Pillar Rule

- Colour follows the pillar of the content, not the page
- Match each callout colour to the content's pillar identity

### Colour Propagation Rule

- Colour propagates throughout the callout
- All section labels and sub-labels inside a callout must use the pillar colour of that callout's content identity
- If the callout header is red (Purpose), every span label and sub-label inside that callout is also red
- The callout header title uses a bold coloured span
- All subsection labels below the header use plain (unbolded) coloured spans, no bold markers
- Do not mix span colours inside a single callout unless a cross-pillar exception applies
- Grey is reserved for maintenance and OS infrastructure callouts only

### Avoiding Overuse

- Avoid highlighting full paragraphs
- Avoid stacking multiple colours
- Maintain a calm visual structure

## Trademark Symbol

Always use the plain text `™` character, never the emoji. Use it in body text,
headings, and callouts only. Do not include `™` in page titles.
